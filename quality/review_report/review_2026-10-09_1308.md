# Next.js Code Review Report - 2026-10-09 13:08

## Summary
- **Conclusion:** ⚠️ Changes required
- **Scope:** Projet entier (`src/`, `prisma/`, scripts, configuration et dépendances), audit de sécurité statique
- **Stats:** Critical: 0 | High: 1 | Medium: 1 | Low: 0
- **Method:** Analyse des flux d'authentification, des accès API, de l'isolation par organisation, du portail client et du checkout ; vérification des dépendances de production (`pnpm audit --prod`) et recherche de fichiers de secrets suivis par Git.

## Findings

| # | Severity | File | Lines | Finding | Evidence / impact | Confidence |
|---|----------|------|-------|---------|-------------------|------------|
| 1 | HIGH | `prisma/seed.ts` | 20-30 | Identifiants administrateur fixes réappliqués par le seed | Le seed crée ou met à jour un compte `ADMIN` avec un mot de passe codé en dur et rétablit le rôle et l'organisation à chaque exécution. Le fournisseur Credentials de `src/auth.ts:13-27` accepte ces identifiants. Si le seed est exécuté contre une base déployée, une personne connaissant le dépôt peut accéder au compte administrateur. La documentation indique toutefois que le seed sert aux données de démonstration locales ; l'exposition d'un déploiement dépend de son exécution sur cet environnement. | 9/10 |
| 2 | MEDIUM | `src/app/api/appointments/[id]/checkout/route.ts` ; `src/schemas/appointments.ts` | `route.ts:27,50-56` ; `appointments.ts:39-55` | Montants de checkout contrôlés par le client | La route valide les types et limites, puis persiste `totalPrice`, les prix d'extras et les données de vente de produits transmis par le client, sans recalcul depuis les prix enregistrés. Un membre authentifié de l'organisation peut forger la requête et fausser les montants et données de vente stockés. | 9/10 |

## Refactoring Plan
1. HIGH — Retirer le compte administrateur privilégié du seed général ou exiger des identifiants fournis hors du code ; ne pas réinitialiser un compte existant.
2. MEDIUM — Recalculer les montants de checkout côté serveur à partir des prix persistés et valider séparément les ajustements autorisés.

## Conclusion
Deux constats de sécurité ont été confirmés. L'audit est statique : il ne vérifie pas la configuration réelle des déploiements ni les données de production. Aucun avis de dépendance n'a été retenu comme vulnérabilité exploitable dans le code exposé. Les risques de déni de service et l'absence de limitation de débit ont été exclus de cette revue.
